# Trafilatura外部基线对照说明

## 目的

项目一原有回归只能回答“这次改动有没有改变固定样例”，不能说明规则输出与其他正文抽取器相差多远。本轮引入 [adbar/trafilatura](https://github.com/adbar/trafilatura) 作为独立传统提取基线，补充可复现的差异检查。

需要先明确边界：Trafilatura是外部参照，不是人工金标。它的结果可以帮助定位漏提、多提和分块差异，但不能单独判定哪一边语义正确。

## 复现命令

在 `web-body-extractor` 目录执行：

~~~powershell
.\.venv\Scripts\python.exe -X utf8 .\app.py baseline
~~~

默认读取：

- `samples/manifest.json`：9篇历史新闻/博客页面。
- `samples/pydoc_manifest.json`：6篇 Python 官方 Sphinx 文档页面。

输出：

- `output/trafilatura_comparison.json`：逐页指标、差异片段和汇总。
- `output/trafilatura_reference/*.json`：每页 Trafilatura 的原始结果。
- `reports/trafilatura_comparison.html`：便于阅读的对照报告。
- `reports/trafilatura_comparison.md`：表格形式的简要报告。

固定依赖为 `trafilatura==2.3.1`。基线调用使用默认回退路径，关闭评论和图片，保留表格，不启用 fast 或 precision/recall偏向。

## 对照口径

1. 两边都做 Unicode NFKC 和空白规范化。
2. 去掉 Sphinx 标题末尾的段落链接标记 `¶`。
3. 标题单独检查，不参加正文字符指标。
4. 规则结果只把 `blocks` 正文块送入F1，已分类的作者、责任编辑、来源、发布时间和制作署名进入单独的“页面信息”列，不参加正文指标。
5. 去掉 Trafilatura 行首的项目符号或编号符号后，按字符5-gram计算精确率、召回率和F1。
6. 使用文本块序列比对辅助观察顺序；分块粒度不同会造成该指标偏低。
7. 任一精确率、召回率或F1低于0.9时标记“需人工核查”，不自动判定对错。

| 新浪新闻 | 3 | 0.972至0.986 | 正文高度一致；基线额外带入推荐、直播或滚动播报组件 |

汇总：15/15页运行成功，15/15标题一致，平均字符5-gram F1为0.9169，3页标记为需人工核查。

## 差异解释

### Python标准库目录页

`pydoc_library_index` 的基线只输出5段导语，我们的规则输出39个块，F1因此降到0.1494。原始HTML中，导语之后是 `div.toctree-wrapper`，里面是从“概述”到“安全考量”的标准库目录。

该页不是普通文章。目录列表属于页面的主要可见内容，保留它更符合“提取网页主要内容”的目标。因此本轮没有为了提升相似度而删除目录，也没有把这一页判为规则错误。更合适的后续做法是把“文章页”和“索引页”分开评价，而不是只用同一套正文指标。

### Paul Graham博客

三篇博客的字符F1为0.989至1.000，但Trafilatura常把整篇合并成1至7段，我们的规则按 `br` 和段落保留67至141块。序列比因此可能很低，但这是分块粒度差异，不是文字顺序错误。

这说明字符指标和块序列指标需要一起解释。只看字符F1会忽略结构差异，只看块序列会误伤合理的合并或拆分。

### 基线也会带入杂质

`chinanews_01` 和 `chinanews_03` 的 Trafilatura 独有片段包含“国内新闻精选”或“东西问精选”的时间列表；新浪样例中包含责任编辑、直播推荐或滚动播报。Trafilatura的输出不能直接作为正确答案。

对照报告中的“页面信息”列会列出规则抽取得到的作者、责任编辑、来源、发布时间和制作署名。Trafilatura参照结果里出现的同名文字，如果已经在这些字段中保留，又不属于正文比较范围，就不应被解释为规则漏提。它说明的是正文口径和页面信息口径不同。

## 经验总结

- 外部基线适合发现差异，不适合充当人工金标。
- 每个指标必须有明确的文本范围、规范化和分块口径；正文F1不应混入已分离的页面信息。
- 作者、编辑、来源和发布时间是有用页面信息，应从正文中分离并结构化展示，而不是直接丢弃。
- 页面类型会影响正确标准。文章页和目录/索引页应分开判断。
- 低F1先回到原始HTML，不要先改规则迎合分数。
- 基线结果也应抽样核查，确认它有没有带入推荐、导航或漏掉结构化内容。
- 保存每页原始基线JSON和源代码哈希，才方便后续解释和复现。
- 回归、外部基线对照和人工语义评测是三种不同证据，不能互相替代。

## 不作出的结论

本轮没有报告正文完整率、纯净度、跨站准确率或生产性能。15/15只表示脚本运行成功；0.9169是当前15页的字符相似度，不是模型准确率。图片像素、JavaScript后加载内容、登录页、分页正文和人工语义争议仍未评测。
